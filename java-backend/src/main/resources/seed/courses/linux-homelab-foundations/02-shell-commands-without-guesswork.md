## 2.1 Read the prompt before typing

A typical prompt is anikesh348@hp-codex:~$. It is status text generated by Bash, not part of your command. It tells you the user, host and current directory. The tilde is shorthand for your home directory. The dollar sign usually signals an ordinary shell.

| Prompt piece | Meaning | Why you check it |
| --- | --- | --- |
| anikesh348 | Current account | Confirms whose permissions and home apply |
| hp-codex | Current hostname | Prevents running a command on the wrong machine |
| ~ | Current directory is your home | Relative paths start here |
| $ | Ordinary-user prompt by convention | A # often indicates a root shell with much larger impact |

> Pre-Enter habit
> Before every administrative command, silently answer: which host, which user, which directory, which exact target? This five-second check prevents a large fraction of shell mistakes.

## 2.2 Command grammar: command, options and arguments

```bash
ls -lah /var/log
```

| Token | Role | Meaning here |
| --- | --- | --- |
| ls | Command name | List directory entries |
| -lah | Three short options combined | Long format, include hidden names, human-readable sizes |
| /var/log | Argument | The directory ls should inspect |

Spaces separate words after the shell finishes parsing quotes and expansions. Options conventionally change how a command behaves; arguments identify what it acts upon. These are conventions, not kernel rules, so consult the command's help when unsure. Long options often look like --human-readable.

### Get help without searching the web

--help gives command-specific usage. man opens the installed manual page; press q to leave. apropos searches manual descriptions.

```bash
pwd --help
ls --help | less
man ls
apropos 'list directory'
```

> Why this matters in your homelab
> Installed documentation matches the installed program version and remains available when DNS or internet access fails.

## 2.3 Paths: absolute, relative, dot and dot-dot

Linux exposes one directory tree beginning at /, called the root directory. An absolute path starts with that slash and identifies the same location regardless of the shell's current directory. A relative path does not start with slash and is interpreted from the current directory.

| Path | Type | Meaning |
| --- | --- | --- |
| /home/anikesh348/notes.txt | Absolute | Start at filesystem root, then home, user directory, file |
| notes.txt | Relative | A file named notes.txt in the current directory |
| ./script.sh | Relative | script.sh in the current directory; dot means current directory |
| ../config | Relative | config in the parent directory; dot-dot means parent |
| ~/notes.txt | Shell-expanded | Bash expands ~ to the current user's home directory |

### pwd - print working directory

Every process has a current working directory. pwd asks the shell to print its current directory. $HOME is a variable expanded by Bash; tilde expansion is a separate shell feature.

```bash
pwd
printf 'HOME=%s\n' "$HOME"
printf 'tilde expands to: %s\n' ~/linux-foundations-lab
```

Typical output

```bash
/home/anikesh348
HOME=/home/anikesh348
tilde expands to: /home/anikesh348/linux-foundations-lab
```

### cd - change the shell's directory

cd path changes Bash's own current directory, so it must be a shell builtin. cd - switches to the previous directory. Bare cd returns to your home directory.

```bash
cd ~/linux-foundations-lab
pwd
cd -
cd
pwd
```

## 2.4 Listing and inspecting without changing anything

### ls - list directory entries

Without -d, ls lists the contents of a directory. With -d, it reports the directory entry itself. -l shows metadata; -a includes names beginning with dot; -h formats sizes for humans.

```bash
ls
ls -la
ls -lah ~/linux-foundations-lab
ls -ld /home/anikesh348
```

> Why this matters in your homelab
> The difference between inspecting a directory and its contents matters when diagnosing permissions on parent directories.

### stat - inspect one object precisely

stat exposes filesystem metadata without relying on ls formatting. The custom format prints type, symbolic permissions, octal permissions, owner/group and path.

```bash
stat ~/linux-foundations-lab
stat -c 'type=%F mode=%A numeric=%a owner=%U:%G path=%n' ~/linux-foundations-lab
```

Typical output

```bash
type=directory mode=drwxr-x--- numeric=750 owner=anikesh348:anikesh348 path=/home/anikesh348/linux-foundations-lab
```

### file and readlink - ask what something is

file examines content or executable format. readlink -f resolves a symbolic link chain to a canonical path. On modern Ubuntu, /bin resolves to /usr/bin.

```bash
file /usr/bin/ls
file /etc/hosts
ls -l /bin
readlink -f /bin
```

## 2.5 Creating, copying, moving and removing

These commands change state. The important skill is not memorising them; it is predicting the exact source, destination and replacement behaviour before running them. Use explicit paths and inspect first.

| Command | Purpose | Important behaviour |
| --- | --- | --- |
| mkdir -p path | Create directories | -p creates missing parents and succeeds if the directory already exists |
| touch file | Create an empty file or update timestamps | Does not clear an existing file |
| cp source destination | Copy file bytes and selected metadata | May replace an existing destination; -i asks first |
| mv source destination | Rename or move | Can replace a destination; same-filesystem rename is usually atomic |
| rm file | Unlink a directory entry | No built-in trash; data may become unrecoverable |
| rmdir empty-dir | Remove an empty directory | Refuses if anything remains inside |

> About rm
> Do not begin by learning rm -rf. First learn to resolve and inspect an exact target. Prefer a trash mechanism for personal files. Never combine recursive removal with an unverified variable, wildcard, home directory, workspace root or mount point.

### Hands-on lab: build a small directory tree

> Safety
> Run this lab on hp-codex. It writes only inside ~/linux-foundations-lab.

Step 1 - Create predictable directories

Brace expansion is performed by Bash, producing three path arguments for mkdir.

```bash
mkdir -p ~/linux-foundations-lab/module-2/{input,output,archive}
cd ~/linux-foundations-lab/module-2
```

Step 2 - Create text safely

printf emits exact text. The greater-than redirection creates or replaces each named file.

```bash
printf 'alpha\nbeta\ngamma\n' > input/names.txt
printf 'environment=lab\n' > input/settings.conf
```

Step 3 - Inspect before copying

find prints type and path; sort makes the display deterministic; cp copies the file.

```bash
find . -maxdepth 2 -printf '%y %p\n' | sort
cp -i input/names.txt output/names-copy.txt
```

Step 4 - Rename explicitly

mv changes the pathname. The file's content remains the same.

```bash
mv output/names-copy.txt archive/names-v1.txt
stat archive/names-v1.txt
```

Step 5 - Remove one exact disposable file

The double dash ends option parsing, useful if a filename begins with a dash. test confirms the exact path no longer exists.

```bash
touch output/delete-me.tmp
ls -l output/delete-me.tmp
rm -- output/delete-me.tmp
test ! -e output/delete-me.tmp; printf 'removed=%s\n' "$?"
```

> What success looks like
> Your tree contains two input files and one archived copy; output is empty. You can explain every created, copied, renamed and removed pathname.

## 2.6 Reading text: choose the right view

| Command | Use it when | Example |
| --- | --- | --- |
| cat | A small file can be printed in full | cat /etc/os-release |
| less | You need an interactive, searchable pager | less /var/log/syslog |
| head | You need the first lines | head -n 5 file |
| tail | You need the final lines | tail -n 20 file |
| tail -f | You want to follow appended lines | tail -f application.log |
| sed -n | You need a bounded line range | sed -n '20,40p' file |

Avoid cat on unknown binary files or enormous logs. For production logs, always set a time or line bound so one diagnostic command cannot flood the terminal or consume excessive resources.

## 2.7 Standard input, output, errors and redirection

A newly started command normally receives three open streams. File descriptor 0 is standard input; 1 is standard output; 2 is standard error. By default they connect to the terminal, but the shell can connect them to files or other processes before starting the command.

| Syntax | Meaning | Risk or detail |
| --- | --- | --- |
| > file | Send stdout to file | Creates or truncates the file before the command runs |
| >> file | Append stdout to file | Creates if absent; repeated runs grow it |
| 2> file | Send stderr to file | Stdout still goes to terminal |
| > file 2>&1 | Send stdout and stderr to same destination | Order matters because 2>&1 duplicates current stdout |
| < file | Read stdin from file | The command sees file bytes as input |
| left \| right | Connect left stdout to right stdin | Exit status normally reflects only the rightmost command |

### Watch stdout and stderr separately

printf writes on stdout, so the shell stores it in output.txt. ls reports the missing path on stderr, so that message goes to error.txt. Redirection is set up by Bash before the command executes.

```bash
cd ~/linux-foundations-lab/module-2
printf 'normal output\n' > output.txt
ls /definitely-missing 2> error.txt
printf 'status=%s\n' "$?"
printf '%s\n' '--- stdout file ---'
cat output.txt
printf '%s\n' '--- stderr file ---'
cat error.txt
```

> A common surprise
> If you run sudo command > /root/file, your current unprivileged shell tries to open /root/file before sudo starts command. Elevating the command does not elevate redirection performed by the original shell.

## 2.8 Pipes build a data flow

### Filter a stream

The first process writes three lines. Bash connects that stdout to grep's stdin. Grep keeps lines beginning with al, and sort receives only those matching lines.

```bash
printf 'alpha\nbeta\nalpine\n' | grep '^al' | sort
```

Typical output

```bash
alpha
alpine
```

A pipeline is not a magic compound command: it is several concurrent processes with file descriptors connected by the kernel. This model explains why each stage can fail independently and why an unbounded producer can overwhelm a slow consumer.

### Search lines with grep

-n shows line numbers. Recursive -R searches below the directory, -I skips binary data, and --exclude avoids matching file patterns.

```bash
grep -n 'beta' input/names.txt
grep -RIn --exclude='*.log' 'environment' .
```

### Find pathnames with find

find walks directories. -type f selects regular files; -name tests the basename. Quote the wildcard so Bash passes it to find instead of expanding it early.

```bash
find ~/linux-foundations-lab -type f -name '*.conf' -print
```

## 2.9 Quoting and expansion: Bash rewrites words

| Form | What Bash does | Example result if name=Anikesh |
| --- | --- | --- |
| $name | Expands variable, then may split and glob | Anikesh |
| "$name" | Expands variable but preserves it as one word | Anikesh |
| '$name' | Treats every character literally | $name |
| *.txt | Expands to matching pathnames | a.txt b.txt |
| '*.txt' | Passes a literal asterisk | *.txt |
| $(command) | Replaces syntax with command's stdout | Depends on command |

Quote variable expansions by default: "$path". An unquoted variable containing spaces can become several arguments, and wildcard characters inside it may unexpectedly match files. Use single quotes for literal text and double quotes when selected expansions are required.

### Prove why quoting matters

The unquoted expansion is split at the space and becomes two arguments. The quoted expansion remains one pathname. set -- replaces the shell's positional arguments only for this exercise.

```bash
cd ~/linux-foundations-lab/module-2
printf 'hello\n' > 'input/two words.txt'
path='input/two words.txt'
printf 'unquoted argument count: '; set -- $path; printf '%s\n' "$#"
printf 'quoted argument count: '; set -- "$path"; printf '%s\n' "$#"
cat "$path"
```

Typical output

```bash
unquoted argument count: 2
quoted argument count: 1
hello
```

## 2.10 Chaining commands deliberately

| Operator | When the right side runs | Typical use |
| --- | --- | --- |
| ; | Always, after the left command finishes | Independent sequential commands |
| && | Only if the left command succeeds | Validate, then perform next step |
| \|\| | Only if the left command fails | Fallback or explicit error handling |
| \| | Concurrently, receiving left stdout | Transform a stream |
| & | Starts left command in background | Interactive jobs; requires lifecycle care |

For operational work, check && change && verify expresses a useful dependency: later stages stop if an earlier stage fails. A semicolon would continue blindly. This does not replace backups, rollback or careful command design.

### Hands-on lab: assemble an evidence pipeline

> Safety
> Run this lab on hp-codex. It writes only inside ~/linux-foundations-lab.

Step 1 - Create a deterministic sample

Double percent is required because printf treats percent as format syntax.

```bash
cd ~/linux-foundations-lab/module-2
printf 'INFO start\nWARN disk 78%%\nINFO ready\nERROR nfs timeout\nWARN retry\n' > sample.log
```

Step 2 - Select warnings and errors

grep filters; tee both displays and saves the selected stream.

```bash
grep -E 'WARN|ERROR' sample.log | tee selected.log
```

Step 3 - Count by severity

cut selects the first space-delimited field; sort groups equal values; uniq -c counts adjacent equal lines.

```bash
cut -d' ' -f1 selected.log | sort | uniq -c
```

Step 4 - Capture a bounded report

Braces group commands in the current shell so one redirection captures all stdout.

```bash
{ date --iso-8601=seconds; wc -l sample.log selected.log; tail -n 2 sample.log; } > report.txt
sed -n '1,10p' report.txt
```

> What success looks like
> You produce selected.log containing two WARN lines and one ERROR line, plus report.txt with a timestamp, line counts and the final two source lines.

•  Which program generated each transformation?

•  Why was sort required before uniq -c?

•  Which stream did tee duplicate?
